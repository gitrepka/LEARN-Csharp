# 15.2. Безопасность паролей

Никогда не храни пароли в открытом виде! И даже "просто хеш" — это плохо.

---

## 1. Проблема: Радужные таблицы
Хакеры заранее посчитали хеши для всех популярных паролей (`123456`, `qwerty`). Если они украдут твою базу хешей, они мгновенно найдут совпадения.

---

## 2. Решение: Соль (Salt)
Мы добавляем к паролю случайный мусор ("соль") перед хешированием.
`Hash("123456" + "kjhsdf78s")`
Теперь у двух пользователей с паролем `123456` будут **разные** хеши, потому что у них разная соль.

---

## 3. Алгоритм PBKDF2 (Rfc2898DeriveBytes)
В .NET есть встроенный класс для правильного хеширования паролей с солью. Он специально работает **медленно** (заставляет процессор трудиться), чтобы хакер не мог перебирать миллиарды паролей в секунду.

```csharp
using System.Security.Cryptography;

// Генерация хеша
byte[] salt = RandomNumberGenerator.GetBytes(16);
var pbkdf2 = new Rfc2898DeriveBytes("password123", salt, 100000);
byte[] hash = pbkdf2.GetBytes(20);
```

---

## 4. Резюме
*   Пароль + Соль + Медленный алгоритм = Безопасность.
*   Никогда не изобретай свою криптографию. Используй стандарты .NET.
