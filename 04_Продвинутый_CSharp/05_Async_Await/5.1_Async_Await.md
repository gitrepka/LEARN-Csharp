# 5.1. Async / Await: Асинхронность

Представь, что ты в ресторане. Официант принял заказ и пошел на кухню. Если бы он был **синхронным**, он бы стоял у плиты и ждал, пока еда приготовится, не обслуживая других клиентов.
**Асинхронный** официант оставит заказ повару и пойдет принимать другие заказы, а вернется за едой, когда она будет готова.

---

## 1. Task — Обещание результата

`Task` — это объект, который представляет работу, которая будет выполнена в будущем.

*   `Task` — просто работа (аналог `void`).
*   `Task<string>` — работа, которая вернет строку.

---

## 2. Использование async и await

```csharp
// Метод обязан иметь пометку async
public async Task DownloadFileAsync()
{
    Console.WriteLine("Загрузка началась...");
    
    // await говорит: "Подожди здесь, пока задача не выполнится, 
    // но не блокируй всю программу (поток)".
    await Task.Delay(3000); // Имитация долгой работы (3 сек)
    
    Console.WriteLine("Загрузка завершена!");
}
```

---

## 3. Зачем это нужно?
В приложениях с интерфейсом (Uno, Windows) или играх (Godot) есть один главный поток (UI Thread). Если ты запустишь в нем долгую задачу без асинхронности, окно приложения просто "замерзнет" и перестанет реагировать на клики. `await` позволяет UI-потоку "дышать".

## 4. Практика: Кухонный таймер

### Задание 5.1.1
Напиши метод `static async Task CookPastaAsync()`.
1. Выведи "Ставим воду".
2. Жди 2 секунды (`Task.Delay`).
3. Выведи "Вода закипела, кладем пасту".
4. Жди 3 секунды.
5. Выведи "Паста готова!".
Запусти метод из `Main` и убедись, что ты можешь выводить что-то еще в консоль, пока паста "готовится".
