dotnet CLI — полный разбор

Как устроена любая команда

Каждая команда dotnet строится по одному принципу:

dotnet [команда] [аргументы] [опции/флаги]

Это как предложение:
- dotnet — "Эй, .NET, сделай..."
- команда — "...вот это действие..."
- аргументы — "...с этой штукой..."
- опции — "...вот таким способом"

Пример:
dotnet new console -n MyApp -o ./projects
│      │   │        │       │
│      │   │        │       └─ опция: куда положить файлы
│      │   │        └─ опция: как назвать проект
│      │   └─ аргумент: какой шаблон
│      └─ команда: создать новое
└─ вызов .NET

  ---
Опции и флаги — что за -n, -o, --name?

У опций есть короткая и длинная форма. Это одно и то же:

-n MyApp          ← короткая форма
--name MyApp      ← длинная форма (полное слово)

Короткая — быстрее набирать. Длинная — понятнее читать. Работают одинаково.

Ещё примеры:
┌──────────┬─────────────────┬───────────────────────────────┐
│ Короткая │     Длинная     │          Что значит           │
├──────────┼─────────────────┼───────────────────────────────┤
│ -n       │ --name          │ Имя проекта                   │
├──────────┼─────────────────┼───────────────────────────────┤
│ -o       │ --output        │ Папка, куда создать           │
├──────────┼─────────────────┼───────────────────────────────┤
│ -f       │ --framework     │ Версия .NET                   │
├──────────┼─────────────────┼───────────────────────────────┤
│ -v       │ --verbosity     │ Сколько подробностей выводить │
├──────────┼─────────────────┼───────────────────────────────┤
│ -c       │ --configuration │ Debug или Release             │
└──────────┴─────────────────┴───────────────────────────────┘
Флаг — это опция без значения, просто вкл/выкл:
dotnet build --no-restore       ← флаг: не восстанавливать пакеты
dotnet run --no-build           ← флаг: не пересобирать

Все важные команды по группам

Группа 1: Создание (dotnet new)

# Посмотреть все доступные шаблоны
dotnet new list

# Создать консольное приложение
dotnet new console -n MyApp

# Создать консольное приложение в конкретной папке
dotnet new console -n MyApp -o ./src/MyApp

# Создать библиотеку классов (не запускается сама, используется другими)
dotnet new classlib -n MyLibrary

# Создать Solution
dotnet new sln -n MySolution

# Создать с конкретной версией .NET
dotnet new console -n MyApp -f net10.0

# Создать .gitignore для .NET проектов
dotnet new gitignore

console, classlib, sln, gitignore — это шаблоны. Их много, dotnet new list покажет все.

  ---
Группа 2: Сборка и запуск

# Скомпилировать проект (проверить ошибки, создать .dll/.exe)
dotnet build

# Скомпилировать и запустить
dotnet run

# Запустить конкретный проект (если их несколько)
dotnet run --project ./src/MyApp

# Запустить в режиме Release (оптимизированный код)
dotnet run -c Release

# Запустить с автоперезапуском при изменении кода (hot reload)
dotnet watch run

# Только собрать, без восстановления пакетов (быстрее)
dotnet build --no-restore

dotnet watch — следит за файлами. Изменил код → автоматически пересобрал и перезапустил. Очень удобно при разработке.

  ---
Группа 3: Пакеты (NuGet — магазин библиотек)

# Добавить пакет в проект
dotnet add package Newtonsoft.Json

# Добавить конкретную версию
dotnet add package Newtonsoft.Json --version 13.0.3

# Удалить пакет
dotnet remove package Newtonsoft.Json

# Восстановить все пакеты (скачать зависимости)
dotnet restore

dotnet restore — скачивает все пакеты, указанные в .csproj. Rider делает это автоматически, но иногда нужно вручную.

  ---
Группа 4: Solution — управление проектами

# Создать Solution
dotnet new sln -n MySolution

# Добавить проект в Solution
dotnet sln add ./src/MyApp/MyApp.csproj

# Добавить несколько проектов
dotnet sln add ./src/MyApp/ ./src/MyLibrary/

# Посмотреть что в Solution
dotnet sln list

# Убрать проект из Solution
dotnet sln remove ./src/MyApp/MyApp.csproj

  ---
Группа 5: Информация

# Версия SDK
dotnet --version

# Подробная информация (SDK, Runtime, OS)
dotnet --info

# Список установленных SDK
dotnet --list-sdks

# Список установленных рантаймов
dotnet --list-runtimes

  ---
Группа 6: Публикация (когда готов отдать другим)

# Опубликовать (создать готовый к запуску пакет)
dotnet publish

# Опубликовать как один файл
dotnet publish -c Release --self-contained -r linux-x64

#   -c Release           ← оптимизированная сборка
#   --self-contained     ← включить .NET внутрь (не нужна установка .NET)
#   -r linux-x64         ← для какой платформы (linux/windows/mac)

  ---
Откуда знать какие опции есть?

Добавь --help к любой команде:

dotnet --help              # общая помощь
dotnet new --help          # помощь по созданию
dotnet new console --help  # помощь по конкретному шаблону
dotnet build --help        # помощь по сборке

Это работает для любой команды. Не нужно ничего запоминать — --help всегда подскажет.

  ---
Шпаргалка — команды на каждый день

dotnet new console -n Имя     ← создать проект
dotnet build                  ← собрать
dotnet run                    ← запустить
dotnet watch run              ← запустить с auto-reload
dotnet add package Имя        ← добавить библиотеку
dotnet restore                ← скачать зависимости
dotnet --help                 ← забыл? спроси помощь

Мини-упражнение

Выполни в терминале Rider:

1. dotnet --info — посмотри свою версию SDK и Runtime
2. dotnet new list — пролистай шаблоны, найди console и classlib
3. dotnet build --help — прочитай какие опции есть у build
