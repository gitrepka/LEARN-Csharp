# 17.1. Git Advanced: Работа в большой команде

Когда над кодом работают 10 человек, простого `commit` недостаточно. Нужно уметь держать историю чистой и решать конфликты без боли.

---

## 1. Merge vs Rebase

### Git Merge
Создает новый "коммит слияния".
*   ✅ Сохраняет историю как она была.
*   ❌ Засоряет дерево лишними коммитами "Merge branch...".

### Git Rebase (Перебазирование)
Переписывает твою ветку так, будто ты начал ее делать от самого последнего коммита в `main`.
*   ✅ История выглядит как прямая линия.
*   ❌ **Опасно**: Никогда не делай rebase в публичных ветках (только в своих feature-ветках).

```bash
git checkout feature/new-logic
git rebase main
```

---

## 2. Полезные инструменты

### Git Stash (Карман)
Если тебе нужно срочно переключить ветку, но код еще не доделан и коммитить его стыдно:
```bash
git stash        # спрятать изменения
git checkout main
# ... поработал ...
git checkout feature/logic
git stash pop    # достать изменения обратно
```

### Git Cherry-pick (Сбор вишен)
Позволяет выдернуть ОДИН конкретный коммит из другой ветки и применить его к себе.
```bash
git cherry-pick <commit-hash>
```

---

## 3. Разрешение конфликтов

Конфликт случается, когда два человека изменили **одну и ту же строку**.
1. Git пометит файл знаками `<<<<<<<` и `>>>>>>>`.
2. Выбери, чей код оставить (или объедини оба).
3. `git add <file>` и `git rebase --continue`.

---

## 4. .gitignore для .NET 10

Убедись, что твой `.gitignore` содержит:
*   `bin/`, `obj/` (результаты сборки)
*   `.vs/`, `.idea/` (настройки IDE)
*   `*.user`, `*.suo` (личные настройки)
*   `appsettings.Development.json` (если там есть секреты)

## 5. Практика: Гигиена Git

### Задание 17.1.1
1. Создай ветку `fix/bug`.
2. Сделай 3 мелких коммита.
3. Используй `git rebase -i main` (интерактивный ребейс), чтобы объединить (squash) эти 3 коммита в один красивый коммит с понятным описанием.
4. Убедись, что история стала чистой.

---

## 6. Резюме
*   **Merge** — для истории, **Rebase** — для красоты.
*   **Stash** — когда нужно бросить всё и уйти на другую ветку.
*   **PR** — твой код должен проверить кто-то другой.
