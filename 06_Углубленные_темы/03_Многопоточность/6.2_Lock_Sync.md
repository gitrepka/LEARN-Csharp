# 6.2. Синхронизация: Оператор lock

Когда два потока одновременно пытаются изменить **одну и ту же** переменную, происходит катастрофа. Это называется **Race Condition** (Состояние гонки).

---

## 1. Пример катастрофы

```csharp
int count = 0;

// Запускаем 1000 потоков, каждый прибавляет 1
for (int i = 0; i < 1000; i++)
{
    Task.Run(() => { count++; });
}

Thread.Sleep(2000);
Console.WriteLine(count); // Скорее всего выведет НЕ 1000! (например, 984)
```
Почему? Потому что `count++` — это три операции: прочитать, прибавить, записать. Два потока могут одновременно прочитать "5", оба прибавят 1 и оба запишут "6". Одна единица потерялась.

---

## 2. Оператор lock (Замок)
`lock` гарантирует, что только **один** поток может зайти в блок кода. Остальные будут стоять в очереди и ждать.

```csharp
private static readonly object _locker = new object();
int count = 0;

// ... внутри задачи ...
lock (_locker)
{
    count++;
}
```

---

## 3. Interlocked: Атомарные операции
Для простых действий (прибавить, убавить) есть специальные быстрые методы. Они работают на уровне процессора без замков.

```csharp
Interlocked.Increment(ref count); // Безопасно и быстро
```

## 4. Практика: Банкомат

### Задание 6.2.1
Создай класс `Account` с балансом.
1. Запусти 10 потоков.
2. Каждый поток должен 1000 раз снять 1 рубль и 1000 раз положить 1 рубль.
3. В конце баланс должен остаться нулевым.
4. Сначала сделай без `lock` (увидишь ошибку), а затем исправь с помощью `lock`.

---

## 5. Резюме
*   Общие данные в потоках — это опасно.
*   `lock` — простая и надежная защита.
*   `Interlocked` — для быстрой арифметики.
