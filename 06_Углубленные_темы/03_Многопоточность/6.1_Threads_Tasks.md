# 6.1. Многопоточность: Потоки и Задачи

Твой процессор имеет несколько ядер. По умолчанию C# использует только одно. Многопоточность позволяет программе делать несколько дел одновременно (например, качать файл и показывать анимацию).

---

## 1. Проблема одного потока
Если ты запустишь бесконечный цикл в главном потоке, твоё окно приложения "замрет". Оно не сможет даже перерисоваться, потому что процессор занят твоим циклом.

---

## 2. Современный подход: Task.Run
Раньше использовали класс `Thread`, но он слишком тяжелый. Сейчас всё делают через **Задачи (Tasks)**.

```csharp
Console.WriteLine("Начинаю тяжелую работу...");

// Запускаем код в фоновом потоке
Task.Run(() => 
{
    for (int i = 0; i < 5; i++)
    {
        Thread.Sleep(1000); // Имитация работы
        Console.WriteLine($"Фоновый поток: шаг {i}");
    }
});

Console.WriteLine("Главный поток свободен и может делать что-то еще!");
Console.ReadLine(); // Ждем, чтобы программа не закрылась сразу
```

---

## 3. Возврат значения из потока
`Task.Run` может возвращать результат.

```csharp
Task<int> task = Task.Run(() => {
    return 42;
});

// Дожидаемся результата (блокирует поток!)
int result = task.Result; 
```
*Заметка:* Использовать `.Result` — плохо. Правильно использовать `await`, как мы учили в теме 14.1.

---

## 4. Практика: Фоновые вычисления

### Задание 6.1.1
Напиши программу, которая:
1. В главном потоке постоянно просит пользователя ввести текст и выводит его обратно.
2. Одновременно с этим в фоновом потоке (`Task.Run`) раз в 5 секунд выводит сообщение: "Проверка обновлений...".

---

## 5. Резюме
*   Многопоточность нужна для отзывчивости интерфейса.
*   `Task.Run` — самый простой способ уйти в фон.
*   Никогда не делай тяжелые вычисления в UI-потоке.
