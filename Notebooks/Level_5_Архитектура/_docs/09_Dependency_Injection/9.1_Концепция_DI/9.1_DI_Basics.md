# 9.1. Dependency Injection: Внедрение зависимостей

Это самая важная тема для работы в команде и на больших проектах. 

---

## 1. Проблема: Жесткая связь
Представь класс `Game`, который внутри себя создает `new FileLogger()`.
Если завтра ты захочешь заменить его на `CloudLogger`, тебе придется лезть в код `Game` и всё переписывать. Это плохо.

---

## 2. Решение: Инъекция через конструктор
Мы не создаем объекты сами. Мы просим их у того, кто нас вызывает.

```csharp
interface ILogger { void Log(string msg); }

class Game
{
    private readonly ILogger _logger;

    // Нам всё равно, какой именно логгер дадут. 
    // Главное, что он реализует ILogger.
    public Game(ILogger logger)
    {
        _logger = logger;
    }

    public void Start() => _logger.Log("Игра запущена");
}
```

---

## 3. DI-Контейнер
В реальных проектах (и в Uno Platform) есть специальный "умный ящик" — **DI-Container**. 
Ты один раз регистрируешь в нем связи: `"На каждый запрос ILogger давай объект FileLogger"`. 
И дальше контейнер сам создает все объекты и вставляет их в конструкторы.
