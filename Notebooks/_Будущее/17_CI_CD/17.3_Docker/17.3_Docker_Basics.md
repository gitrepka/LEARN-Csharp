# 17.3. Docker: Контейнеризация приложений .NET 10

Docker — это стандарт де-факто для развертывания серверных приложений. Он гарантирует, что твой код будет работать одинаково и на твоем ПК, и на сервере в облаке.

---

## 1. Dockerfile для .NET 10 (Multi-stage Build)

Мы используем "многоэтапную сборку": на первом этапе компилируем код (нужен тяжелый SDK), на втором — только запускаем (нужен легкий Runtime).

```dockerfile
# ЭТАП 1: Сборка (Build)
FROM mcr.microsoft.com/dotnet/sdk:10.0 AS build
WORKDIR /src

# Кэшируем восстановление пакетов (отдельный слой)
COPY ["MyServer/MyServer.csproj", "MyServer/"]
RUN dotnet restore "MyServer/MyServer.csproj"

# Копируем всё остальное и собираем
COPY . .
WORKDIR "/src/MyServer"
RUN dotnet publish "MyServer.csproj" -c Release -o /app/publish /p:UseAppHost=false

# ЭТАП 2: Запуск (Runtime)
FROM mcr.microsoft.com/dotnet/aspnet:10.0-alpine AS final
WORKDIR /app
COPY --from=build /app/publish .

# Безопасность: запуск от не-root пользователя (рекомендация .NET 10)
USER $APP_UID

ENTRYPOINT ["dotnet", "MyServer.dll"]
```

## 2. Основные команды Docker

```bash
# Собрать образ
docker build -t my-server:v1 .

# Запустить контейнер
docker run -d -p 8080:80 --name server-v1 my-server:v1

# Посмотреть логи
docker logs -f server-v1

# Остановить и удалить
docker stop server-v1 && docker rm server-v1
```

## 3. Docker Compose (Для сложных систем)

Если твоему приложению нужна база данных (PostgreSQL), используй `docker-compose.yml`.

```yaml
version: '3.8'
services:
  web:
    build: .
    ports:
      - "8080:80"
    depends_on:
      - db
  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_PASSWORD: mysecretpassword
```

## 5. Резюме
*   **Image (Образ)**: Замороженный слепок программы.
*   **Container (Контейнер)**: Работающий экземпляр образа.
*   **Multi-stage**: SDK для сборки, Runtime для запуска.
*   **Alpine**: Легкая версия Linux для уменьшения размера образа.
