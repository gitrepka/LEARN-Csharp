# 1.2. Организация кода: Пространства имен и Using

Ты научился запускать программу. Теперь давай научимся наводить в ней порядок. Представь, что твой проект — это огромная библиотека. Если свалить все книги в кучу, ты никогда не найдешь нужную.

## 1. Пространства имен (namespace)

`namespace` (пространство имен) — это "фамилия" твоего кода. Это способ сгруппировать связанные классы и избежать конфликтов имен.

Представь, что ты делаешь игру.
У тебя есть класс `Player` (игрок).
И ты подключил библиотеку для воспроизведения видео, где тоже есть класс `Player` (видео-плеер).

Как компилятору понять, какого "Плеера" ты хочешь создать? По фамилии!
*   `MyGame.Logic.Player` — твой герой.
*   `SuperVideoLib.Player` — видео-плеер.

### Как объявить namespace?

#### Способ 1: Классический (Block-scoped)
До C# 10 это был единственный способ. Весь код оборачивается в фигурные скобки.

```csharp
namespace MyGame.Characters
{
    class Hero 
    {
        // Код героя...
    }
}
```
*Минус:* Лишний уровень отступа. Код "уезжает" вправо.

#### Способ 2: Современный (File-scoped) — Рекомендуется!
Появился в C# 10. Пишется в начале файла с точкой с запятой.

```csharp
namespace MyGame.Characters; // <-- Точка с запятой

class Hero 
{
    // Код без лишнего отступа!
}
```
Это означает: "Всё, что в этом файле, принадлежит пространству `MyGame.Characters`".
*Ограничение:* В файле может быть только один такой namespace (что логично).

## 2. Директива using

Мы не хотим каждый раз писать полное имя: `System.Console.WriteLine("Hi");`.
Мы хотим писать просто: `Console.WriteLine("Hi");`.

Для этого мы "подключаем" пространство имен.

```csharp
using System; // Подключили "зал" System

Console.WriteLine("Привет"); // Компилятор ищет Console внутри System
```

### Implicit Usings (Неявные подключения)
В новых проектах .NET (6+) ты можешь заметить, что `using System;` часто не пишут, но `Console` работает.
Это магия файла `.csproj`. Если там есть строка:
`<ImplicitUsings>enable</ImplicitUsings>`
...то компилятор сам неявно добавляет популярные библиотеки (`System`, `System.Linq` и др.) ко всем файлам.

### Global Using
Ты можешь сделать using глобальным для всего проекта.
Создай файл `GlobalUsings.cs` (имя может быть любым) и напиши:

```csharp
global using System.Text;
global using MyGame.Characters;
```
Теперь `StringBuilder` и `Hero` будут доступны **во всех** файлах проекта без лишних строк.

### Using Alias (Псевдонимы)
Иногда имена классов совпадают, и `using` не помогает.
Например, `Date` есть в двух библиотеках.

```csharp
using MyDate = MyLibrary.Date;
using SysDate = System.DateTime;

var d1 = new MyDate();
var d2 = new SysDate();
```

Также можно сокращать длинные типы:
```csharp
// Вместо длинного List<string> будем писать просто Names
using Names = System.Collections.Generic.List<string>;

Names myList = new(); // Это List<string>
```

## 3. Практика

### Задание 1.2.1: Конфликт имен
1.  Создай два файла: `Music.cs` и `Game.cs`.
2.  В `Music.cs` напиши:
    ```csharp
    namespace Multimedia;
    public class Player { public void Play() => Console.WriteLine("Music playing"); }
    ```
3.  В `Game.cs` напиши:
    ```csharp
    namespace Logic;
    public class Player { public void Kill() => Console.WriteLine("Enemy killed"); }
    ```
4.  В `Program.cs` попробуй создать обоих плееров.
    *   Сначала попробуй без `using` (через полные имена).
    *   Потом подключи `using Multimedia;` и посмотри, как обратиться к игровому плееру.

---

## 4. Резюме
*   **namespace** — группирует код и дает ему уникальный адрес. Используй `file-scoped` (с точкой с запятой).
*   **using** — позволяет не писать полные имена.
*   **global using** — подключает namespace сразу ко всему проекту.
