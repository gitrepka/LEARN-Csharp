# 1.2. Свойства (Properties): Умные переменные

В профессиональном коде **никогда** не делают поля `public`. Почему? Потому что в них можно записать бред (например, здоровье -500 или возраст 999).

Свойства — это "защитники" твоих данных.

---

## 1. Классические свойства (get/set)

```csharp
class Player
{
    private int _health; // Закрытое поле (никто снаружи не видит)

    public int Health // Публичное свойство
    {
        get { return _health; } // Чтение
        set 
        { 
            // Валидация!
            if (value < 0) _health = 0;
            else if (value > 100) _health = 100;
            else _health = value; 
        }
    }
}
```
*   `value` — это специальное слово, означающее то, что нам пытаются записать.

---

## 2. Авто-свойства

Если тебе не нужна валидация, можно писать короче. Компилятор сам создаст скрытое поле.

```csharp
public string Name { get; set; }
```

---

## 3. Только для чтения (ReadOnly)

Если убрать `set`, свойство нельзя будет изменить снаружи.

```csharp
public int Id { get; } = 1; // Устанавливается один раз при создании
```

---

## 4. Продвинутые фишки

### init (C# 9)
Позволяет менять значение **только** в момент создания объекта. Потом — нельзя.
```csharp
public string SecretKey { get; init; }
```

### required (C# 11)
Обязывает тебя указать значение при создании объекта. Больше не забудешь дать игроку имя!
```csharp
public required string Name { get; set; }
```

2. Метод `Deposit(decimal amount)`.
3. Метод `Withdraw(decimal amount)` — он должен проверять, хватает ли денег. Нельзя уходить в минус!

## 6. Резюме
*   Поля — всегда `private`.
*   Свойства — всегда `public`.
*   Свойство = Логика защиты данных.
