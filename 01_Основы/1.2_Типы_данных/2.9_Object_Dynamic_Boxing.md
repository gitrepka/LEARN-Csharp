# 2.9. object, dynamic и Boxing

## Что ты узнаешь
- `object` — базовый тип всего в C#
- `dynamic` — тип без проверки компилятором
- Boxing / Unboxing — упаковка значимых типов
- Операторы `is` и `as`

---

## 1. object — прародитель всех типов

В C# **абсолютно всё** наследуется от `object`. Это значит: переменная типа `object` может хранить ЧТО УГОДНО.

```csharp
object a = 42;           // int
object b = "Привет";     // string
object c = true;         // bool
object d = new int[] { 1, 2, 3 }; // массив
```

### Зачем?
- Старые API (до дженериков) использовали `object` повсюду
- `ArrayList` хранит `object` (поэтому сейчас используют `List<T>`)
- Метод `ToString()`, `Equals()`, `GetHashCode()` — все от `object`

---

## 2. Boxing и Unboxing — скрытая цена

Когда ты кладёшь значимый тип (int, bool) в `object`, происходит **boxing** (упаковка):

```csharp
int number = 42;
object boxed = number; // BOXING: int копируется из стека в кучу, оборачивается в объект
```

Обратно — **unboxing**:
```csharp
int unboxed = (int)boxed; // UNBOXING: достаём значение из кучи обратно в стек
```

### Почему это важно?
Boxing — это **медленно**:
1. Выделение памяти в куче
2. Копирование значения
3. Нагрузка на Garbage Collector

```csharp
// ❌ Плохо: 10000 boxing операций!
ArrayList list = new ArrayList();
for (int i = 0; i < 10000; i++)
    list.Add(i); // каждый int упаковывается в object

// ✅ Хорошо: никакого boxing
List<int> list = new List<int>();
for (int i = 0; i < 10000; i++)
    list.Add(i); // int остаётся int
```

**Правило:** Используй дженерики (`List<T>`, `Dictionary<K,V>`) вместо `object`. Boxing — это проблема прошлого, но ты встретишь его в старом коде.

## 3. Операторы is и as

### `is` — проверка типа

```csharp
object item = "Привет";

if (item is string)
    Console.WriteLine("Это строка!");

// С извлечением (pattern matching):
if (item is string text)
    Console.WriteLine($"Строка: {text}, длина: {text.Length}");

// Проверка на null:
if (item is not null)
    Console.WriteLine("Не null");
```

### `as` — безопасное приведение

```csharp
object item = "Привет";

// as возвращает null если тип не совпал (вместо исключения)
string? text = item as string;  // "Привет"
int? number = item as int?;     // null (item — не int)

// Сравни с жёстким кастом:
string text2 = (string)item;     // ✅ Работает
int number2 = (int)item;         // ❌ InvalidCastException!
```

**Когда что:**
- `is` — когда нужно проверить тип (условие)
- `as` — когда нужно попробовать привести тип (может не получиться)
- `(тип)` — когда ты уверен в типе на 100%

---

## 4. dynamic — "отключить компилятор"

`dynamic` говорит компилятору: "Не проверяй, я сам разберусь в runtime".

```csharp
dynamic x = 10;
x = "теперь строка";  // ✅ Нет ошибки компиляции!
x = x + 5;            // Упадёт в runtime! (строка + число)
```

### Когда нужен?
- Работа с COM-объектами (Excel, Word)
- Работа с JSON без десериализации
- Очень редко в обычном коде

**Правило:** Избегай `dynamic`. Он убирает все проверки компилятора — ошибки вылезут только при запуске.

---

## 5. Анонимные типы

Быстрый способ создать объект без объявления класса:

```csharp
var person = new { Name = "Алиса", Age = 25, IsAlive = true };

Console.WriteLine(person.Name);  // "Алиса"
Console.WriteLine(person.Age);   // 25

// person.Name = "Боб"; // ❌ Свойства readonly!
```

- Тип определяется компилятором
- Свойства нельзя менять (immutable)
- Полезны в LINQ-запросах

## Резюме
- `object` — может хранить всё, но теряет информацию о типе
- Boxing — дорогая операция, избегай через дженерики
- `is` — проверка типа, `as` — безопасный каст
- `dynamic` — без проверки компилятора (опасно)
- Анонимные типы — быстрые readonly-объекты
