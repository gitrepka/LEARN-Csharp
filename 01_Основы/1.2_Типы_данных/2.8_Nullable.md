# 2.8. Nullable-типы: борьба с пустотой

## Что ты узнаешь
- Nullable value types (`int?`, `bool?`)
- Nullable reference types (NRT)
- Операторы `HasValue`, `Value`, `GetValueOrDefault()`

> Null-операторы (`??`, `?.`, `??=`) подробно → 3.5

---

## ЗАЧЕМ?

`int` всегда содержит число. Но иногда значения нет — пользователь не заполнил поле, в БД пустая ячейка, у персонажа нет оружия. Нужен способ сказать "тут пусто".

## 1. Nullable Value Types (`int?`)

Обычный `int` не может быть `null`:
```csharp
int age = null; // ❌ Ошибка компиляции! int всегда имеет значение
```

Добавь `?` — и сможет:
```csharp
int? age = null;    // ✅ "Возраст неизвестен"
int? hp = 100;      // ✅ Обычное число тоже работает
bool? isReady = null; // ✅ "Ещё не решил"
```

### Как проверить?

```csharp
int? damage = null;

// Способ 1: HasValue
if (damage.HasValue)
    Console.WriteLine($"Урон: {damage.Value}");
else
    Console.WriteLine("Нет урона");

// Способ 2: сравнение с null
if (damage != null)
    Console.WriteLine($"Урон: {damage}"); // автоматически берёт Value

// Способ 3: GetValueOrDefault
int safeDamage = damage.GetValueOrDefault(0); // если null → 0

// Способ 4: ?? (null-coalescing)
int safeDamage2 = damage ?? 0; // то же самое, короче
```

### Под капотом
`int?` — это `Nullable<int>`. Структура с двумя полями: `HasValue` (bool) и `Value` (int).

---

## 2. Nullable Reference Types (NRT)

Строки, массивы, классы — ссылочные типы. Они ВСЕГДА могли быть null. Проблема: `NullReferenceException` — самая частая ошибка в истории программирования.

C# 8+ ввёл **Nullable Reference Types** — компилятор ПРЕДУПРЕЖДАЕТ если ты забыл проверить null.

### Как включить?
В `.csproj`:
```xml
<Nullable>enable</Nullable>
```

### Как работает?

```csharp
string name = "Алиса";   // Гарантировано НЕ null
string? nick = null;      // Может быть null (помечено ?)

Console.WriteLine(name.Length);  // ✅ Безопасно
Console.WriteLine(nick.Length);  // ⚠️ Предупреждение компилятора!

// Правильно:
if (nick != null)
    Console.WriteLine(nick.Length);  // ✅ Компилятор видит проверку

// Или через ?.
Console.WriteLine(nick?.Length);     // ✅ null если nick == null
```

### Оператор `!` (null-forgiving)

Иногда ТЫ знаешь что значение не null, но компилятор сомневается:
```csharp
string? data = GetData(); // компилятор думает: "может быть null"
string safe = data!;       // ТЫ говоришь: "я уверен, что не null"
```
**Используй редко!** Если ошибёшься — получишь NullReferenceException.

## Резюме
- `int?` — значимый тип который может быть пустым
- `string?` — ссылочный тип, явно помечен как "может быть null"
- `string` (без ?) — гарантия "не null" (при включённом NRT)
- `HasValue`, `??`, `?.` — инструменты для работы с null
