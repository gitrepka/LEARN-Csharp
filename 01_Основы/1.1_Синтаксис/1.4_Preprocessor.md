# 1.4. Препроцессор: Управление компиляцией

Иногда нужно, чтобы часть кода превращалась в программу только при определенных условиях. Например, чит-коды в игре должны работать, пока ты её разрабатываешь, но исчезнуть в финальной версии.

Для этого существуют **директивы препроцессора**. Они начинаются с решетки `#`.

---

## 1. Условная компиляция (#if)

Самая частая конструкция. Она смотрит на **символы компиляции** (Build Symbols).

```csharp
#if DEBUG
    Console.WriteLine("Режим разработчика активирован!");
    // Этот код попадет в .exe только если выбрана конфигурация Debug
#else
    Console.WriteLine("Добро пожаловать, игрок.");
    // А этот — только в Release
#endif
```

### Где переключать режимы?
В IDE (Rider/VS) на верхней панели есть выпадающий список: `Debug` | `Release`.
*   **Debug:** Код не оптимизирован, удобно отлаживать, определен символ `DEBUG`.
*   **Release:** Максимальная оптимизация, символа `DEBUG` нет.

### Свои символы (#define)
Ты можешь объявлять свои символы в начале файла.

```csharp
#define PRO_VERSION // Объявляем символ

using System;

class Program {
    void Main() {
#if PRO_VERSION
        Console.WriteLine("У вас есть доступ к платным функциям.");
#endif
    }
}
```

## 2. Регионы (#region)

Позволяют сворачивать (коллапсировать) куски кода в редакторе. Это чисто визуальная фишка для программиста, на компиляцию не влияет.

```csharp
#region Math Helpers
    int Add(int a, int b) => a + b;
    int Sub(int a, int b) => a - b;
#endregion
```

*Мнение сообщества:* Многие считают регионы "запахом кода" (code smell). Если тебе нужно прятать код в регионы, возможно, твой класс стал слишком большим и его пора разбить на несколько классов. Используй с умом.

---

## 3. Отключение предупреждений (#pragma)

Иногда компилятор "ругается" (Warning), но ты знаешь, что делаешь. Можно заткнуть его точечно.

```csharp
#pragma warning disable CS0168 // Отключить warning "Variable declared but never used"
    int unusedVar; 
#pragma warning restore CS0168 // Включить обратно
```
*Совет:* Никогда не отключай предупреждения глобально. Только точечно вокруг проблемной строки.

## 4. Практика

### Задание 1.4.1: Секретный уровень
1.  Напиши код, который спрашивает пароль.
2.  Оберни проверку пароля в `#if DEBUG`. Сделай так, чтобы в Debug-режиме пароль подходил любой (или вообще не спрашивался), а в Release — требовался настоящий.
3.  Переключи конфигурацию сборки и проверь.
