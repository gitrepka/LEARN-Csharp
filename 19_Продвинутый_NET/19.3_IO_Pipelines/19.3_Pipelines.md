# 19.3. System.IO.Pipelines: Высокопроизводительный I/O

## Введение
Традиционная работа с `Stream` (потоками) имеет проблемы при парсинге данных.
*   Что если мы прочитали пол-строки? Нужно хранить буфер.
*   Что если буфер переполнился? Нужно копировать данные в новый (Array.Resize).
*   Много аллокаций памяти = нагрузка на GC.

**System.IO.Pipelines** решает эти проблемы. Это библиотека, на которой работает Kestrel (веб-сервер ASP.NET Core). Она позволяет парсить данные **без лишних копирований** (zero-copy).

---

## 1. Как это работает: Pipe, Reader, Writer

В центре всего стоит класс `Pipe` (Труба).
*   **PipeWriter**: Пишет данные в трубу (обычно из сети или файла).
*   **PipeReader**: Читает данные из трубы и позволяет их анализировать.

Главная фишка: Память управляется самой трубой. Вы получаете доступ к данным через `ReadOnlySequence<byte>`, который может состоять из нескольких кусков памяти, но для вас выглядит как единое целое.

---

## 2. Пример: Парсинг строк

Допустим, мы читаем данные, разделенные переносом строки (`\n`). Данные могут приходить кусками по 1 байту или сразу по 1000.

```csharp
using System.IO.Pipelines;
using System.Buffers;
using System.Text;

async Task ProcessLinesAsync(Stream stream)
{
    var pipe = new Pipe();
    
    // Запускаем задачу чтения из стрима в пайп (Producer)
    Task writing = FillPipeAsync(stream, pipe.Writer);
    
    // Запускаем задачу обработки данных (Consumer)
    Task reading = ReadPipeAsync(pipe.Reader);

    await Task.WhenAll(writing, reading);
}

async Task FillPipeAsync(Stream stream, PipeWriter writer)
{
    while (true)
    {
        // Просим у пайпа кусок памяти
        Memory<byte> memory = writer.GetMemory(512);
        
        // Читаем из стрима прямо в этот кусок
        int bytesRead = await stream.ReadAsync(memory);
        if (bytesRead == 0) break; // Конец данных

        // Сообщаем пайпу, сколько реально записали
        writer.Advance(bytesRead);

        // Делаем данные доступными для Reader-а
        FlushResult result = await writer.FlushAsync();
        if (result.IsCompleted) break;
    }
    await writer.CompleteAsync();
}

async Task ReadPipeAsync(PipeReader reader)
{
    while (true)
    {
        ReadResult result = await reader.ReadAsync();
        ReadOnlySequence<byte> buffer = result.Buffer;

        // Обрабатываем всё, что успели получить
        while (TryReadLine(ref buffer, out ReadOnlySequence<byte> line))
        {
            ProcessLine(line);
        }

        // Сообщаем пайпу: 
        // 1. consumed: до какого места мы точно всё обработали (эту память можно освобождать)
        // 2. examined: до какого места мы просмотрели (но не нашли конца строки)
        reader.AdvanceTo(buffer.Start, buffer.End);

        if (result.IsCompleted) break;
    }
    await reader.CompleteAsync();
}

bool TryReadLine(ref ReadOnlySequence<byte> buffer, out ReadOnlySequence<byte> line)
{
    // Ищем символ переноса строки
    SequencePosition? position = buffer.PositionOf((byte)'\n');

    if (position == null)
    {
        line = default;
        return false;
    }

    // Отрезаем кусок до переноса строки
    line = buffer.Slice(0, position.Value);
    
    // Сдвигаем буфер вперед (пропускаем саму строку и \n)
    buffer = buffer.Slice(buffer.GetPosition(1, position.Value));
    return true;
}
```

---

## 3. Основной цикл Reader-а
1.  `await reader.ReadAsync()`: Ждем данные.
2.  `result.Buffer`: Получаем доступ к данным.
3.  Парсим в цикле (`while`), пока можем извлечь полные сообщения.
4.  `reader.AdvanceTo(consumed, examined)`: Критически важно!
    *   Если не вызвать, `ReadAsync` вернет те же данные (бесконечный цикл).
    *   Если сказать, что всё обработано, данные удалятся из памяти.

---

## 4. Резюме
Используй Pipelines, когда пишешь высоконагруженные серверы или парсеры сетевых протоколов. Для обычного чтения файлов `FileStream` обычно достаточно. Pipelines — это инструмент для экстремальной оптимизации.
