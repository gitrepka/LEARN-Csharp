> *Закрепляет: понимание GC (почему много аллокаций — плохо), ArrayPool, Span vs копирование, boxing на практике, Dispose (pool.Return), замеры производительности*

#### Блок D: SOLID и паттерны проектирования

### [5.7 SOLID](./Level_5_Архитектура/07_SOLID/)
- **S** — Single Responsibility: класс = одна задача
- Как выявить нарушение SRP
- Рефакторинг: разделение класса
- **O** — Open/Closed: расширяй, не меняй
- Добавление поведения через наследование/интерфейсы
- **L** — Liskov Substitution: потомок заменяет родителя
- Нарушение: переопределение с другим поведением
- **I** — Interface Segregation: маленькие интерфейсы
- Разделение большого интерфейса на несколько
- **D** — Dependency Inversion: зависи от абстракций
- Интерфейс вместо конкретного класса

### [5.8 Singleton](./Level_5_Архитектура/08_Singleton/)
- Единственный экземпляр класса
- Приватный конструктор
- Статическое свойство `Instance`
- Thread-safe с `Lazy<T>`
- Когда использовать (и когда НЕ использовать)

### [5.9 Factory Method](./Level_5_Архитектура/09_Factory_Method/)
- Создание объекта через метод, не через `new`
- Интерфейс создателя
- Конкретные создатели
- Когда использовать

### [5.10 Strategy](./Level_5_Архитектура/10_Strategy/)
- Семейство алгоритмов через интерфейс
- Контекст хранит ссылку на стратегию
- Замена алгоритма в runtime
- Пример: разные способы сортировки/оплаты

### [5.11 Observer](./Level_5_Архитектура/11_Observer/)
- Подписка на изменения
- Publisher (издатель) уведомляет
- Subscriber (подписчик) реагирует
- Реализация через events
- Реализация через интерфейс

### [5.12 State](./Level_5_Архитектура/12_State/)
- Конечный автомат (FSM)
- Состояние как объект
- Переходы между состояниями
- Пример: состояния игрового персонажа

### [5.13 Command](./Level_5_Архитектура/13_Command/)
- Действие как объект
- Интерфейс `ICommand` с `Execute()` / `Undo()`
- История команд
- Undo/Redo

### [5.14 Builder](./Level_5_Архитектура/14_Builder/)
- Пошаговое построение сложного объекта
- Fluent API: `builder.SetName("...").SetAge(25).Build()`
- Director — управляет порядком

### [5.15 Decorator](./Level_5_Архитектура/15_Decorator/)
- Обёртка для добавления поведения
- Тот же интерфейс, дополнительная логика
- Вложенные декораторы
- Пример: логирование, кэширование

> **Мини-проект: «Текстовый редактор с Undo»**
> **Command**: `ICommand` с Execute/Undo — InsertTextCommand, DeleteTextCommand, ReplaceTextCommand. Stack для истории — Undo/Redo. **Strategy**: `IFormatter` с реализациями UpperCaseFormatter, TrimFormatter, MarkdownToHtmlFormatter — пользователь выбирает стратегию. **Observer**: событие OnTextChanged — подписчики: автосохранение, подсчёт слов, подсветка синтаксиса. **Factory**: метод CreateCommand("insert", args) вместо switch. **Decorator**: LoggingFormatter оборачивает любой IFormatter и логирует. **SOLID**: каждый класс — одна ответственность, зависимости через интерфейсы.
> *Закрепляет: все 5 паттернов в одном связном проекте, SOLID на практике (каждый принцип виден в коде)*

#### Блок E: Архитектура приложений

### [5.16 MVVM](./Level_5_Архитектура/16_MVVM/)
- Model — данные
- View — интерфейс (XAML)
- ViewModel — логика между Model и View
- `INotifyPropertyChanged` — уведомление об изменении свойства
- `PropertyChanged` событие
- `ICommand` — привязка команд к кнопкам
- `CommunityToolkit.Mvvm` — Source Generators вместо бойлерплейта
- `[ObservableProperty]`, `[RelayCommand]` — автогенерация кода
- Data Binding — связь View ↔ ViewModel
- OneWay, TwoWay, OneTime binding

### [5.17 Clean Architecture](./Level_5_Архитектура/17_Clean_Architecture/)
- Слои: Domain → Application → Infrastructure → Presentation
- Domain — бизнес-логика (без зависимостей)
- Application — use cases
- Infrastructure — БД, API, файлы
- Presentation — UI
- Repository pattern — абстракция доступа к данным
- CQRS — разделение чтения и записи (обзор)

### [5.18 Dependency Injection](./Level_5_Архитектура/18_Dependency_Injection/)
- Что такое DI (внедрение зависимостей)
- Constructor injection — через конструктор
- `IServiceCollection` — регистрация сервисов
- `AddTransient<T>` — новый экземпляр каждый раз
- `AddScoped<T>` — один на запрос
- `AddSingleton<T>` — один на всё приложение
- `IServiceProvider` — получение сервисов
- Регистрация интерфейс → реализация

### [5.19 Логирование](./Level_5_Архитектура/19_Логирование/)
- Зачем логировать
- `Microsoft.Extensions.Logging`
- `ILogger<T>` — логгер с типом
- Уровни: Trace, Debug, Information, Warning, Error, Critical
- `LogInformation()`, `LogWarning()`, `LogError()`
- Structured logging — параметры в сообщении
- `LoggerMessage.Define()` — высокопроизводительное логирование (старый API)
- `[LoggerMessage]` — современный подход через Source Generator
- Serilog — популярная библиотека (обзор)
- Запись в файл, консоль, БД

### [5.20 Unit Testing — основы](./Level_5_Архитектура/20_Unit_Testing/)
- Зачем тестировать (ловить баги до запуска, рефакторинг без страха)
- Тестовый проект: `dotnet new xunit`
- Атрибут `[Fact]` — простой тест
- Атрибут `[Theory]` + `[InlineData]` — параметризованный тест
- `Assert.Equal()`, `Assert.True()`, `Assert.False()`
- `Assert.Throws<T>()` — проверка исключений
- `Assert.Contains()`, `Assert.Empty()`
- Паттерн AAA: Arrange → Act → Assert
- Именование тестов: `МетодName_Сценарий_ОжидаемыйРезультат`
- Запуск тестов: `dotnet test`
- Тестирование в Rider / VS Code

### [5.21 Стиль кода](./Level_5_Архитектура/21_Стиль_кода/)
- PascalCase — классы, методы, свойства, публичные поля
- camelCase — локальные переменные, параметры
- _camelCase — приватные поля
- `I` + PascalCase — интерфейсы
- `.editorconfig` — настройки стиля для проекта
- Roslyn analyzers — автоматические проверки
- XML-документация: `/// <summary>`, `<param>`, `<returns>`

> **Мини-проект: «Мини-приложение с Clean Architecture»**
> Консольный менеджер заметок с полной архитектурой. **Domain**: `Note` (entity), `INotesRepository` (интерфейс). **Application**: `CreateNoteUseCase`, `ListNotesUseCase`, `SearchNotesUseCase`. **Infrastructure**: `JsonNotesRepository` (сохранение в JSON-файл), реализует `INotesRepository`. **Presentation**: консольное меню. **DI**: `IServiceCollection` для регистрации, constructor injection везде. **Logging**: `ILogger` для отслеживания операций. **MVVM-основа**: `NoteViewModel` с `INotifyPropertyChanged` (подготовка к Uno).
> *Закрепляет: Clean Architecture (все 4 слоя), DI (регистрация и injection), Repository pattern, ILogger, MVVM-основы, стиль кода (editorconfig), **unit-тесты** (тесты на use cases и repository). Это фундамент для будущих Uno/Godot проектов.*
